## 2\. Java 语言基础

### 2.1 Java 是什么？

Java 是一种**面向对象**的编程语言，具有以下特点：

-   **跨平台**：一次编写，到处运行（Write Once, Run Anywhere）
    
-   **强类型**：变量必须先声明类型
    
-   **自动内存管理**：垃圾回收器（GC）自动释放内存
    
-   **丰富的标准库**：提供大量现成的工具类
    

**为什么 Minecraft 使用 Java？**

-   Minecraft Java 版最初用 Java 编写
    
-   模组开发需要与游戏代码交互，因此必须使用 Java

```java
// 引用类型：存储对象的地址
```


### 2.7 面向对象编程（OOP）核心概念

#### 2.7.1 类与对象

**类（Class）**：对象的模板，定义了对象的属性和行为。

**对象（Object）**：类的实例，具体的实体。

```java
// 定义一个类
public class Sword {
    // 属性（字段）
    private int damage;
    private int durability;
    
    // 构造函数
    public Sword(int damage, int durability) {
        this.damage = damage;
        this.durability = durability;
    }
    
    // 方法
    public void attack() {
        System.out.println("造成 " + damage + " 点伤害");
        durability--;
    }
    
    // Getter 方法
    public int getDamage() {
        return damage;
    }
    
    // Setter 方法
    public void setDamage(int damage) {
        this.damage = damage;
    }
}

// 创建对象
Sword ironSword = new Sword(7, 250);
ironSword.attack();  // 调用方法
int damage = ironSword.getDamage();  // 获取属性
```

**关键概念：**

-   `this` — 指向当前对象
    
-   `private` — 私有属性，只能在类内部访问
    
-   `public` — 公开方法，可以在任何地方访问
    
-   构造函数 — 与类同名，用于初始化对象
    

#### 2.7.2 封装（Encapsulation）

封装是将数据（属性）和操作数据的方法绑定在一起，并隐藏内部实现细节。

```java
public class Item {
    // 私有属性，外部无法直接访问
    private int maxStackSize;
    
    // 通过公开方法访问
    public int getMaxStackSize() {
        return maxStackSize;
    }
    
    // 通过公开方法修改，可以添加验证逻辑
    public void setMaxStackSize(int size) {
        if (size > 0 && size <= 64) {
            this.maxStackSize = size;
        } else {
            throw new IllegalArgumentException("堆叠数量必须在 1-64 之间");
        }
    }
}
```

**为什么要封装？**

-   保护数据不被随意修改
    
-   可以在 setter 中添加验证逻辑
    
-   隐藏实现细节，降低耦合度
    

#### 2.7.3 继承（Inheritance）

继承允许一个类（子类）继承另一个类（父类）的属性和方法。

```java
// 父类
public class Item {
    protected int maxStackSize;
    
    public Item(Properties properties) {
        this.maxStackSize = properties.maxStackSize;
    }
    
    public int getMaxStackSize() {
        return maxStackSize;
    }
}

// 子类继承父类
public class SwordItem extends Item {
    private int attackDamage;
    
    public SwordItem(Properties properties, int attackDamage) {
        super(properties);  // 调用父类构造函数
        this.attackDamage = attackDamage;
    }
    
    // 子类特有的方法
    public int getAttackDamage() {
        return attackDamage;
    }
}
```

**关键概念：**

-   `extends` — 继承关键字
    
-   `super` — 调用父类的构造函数或方法
    
-   `protected` — 受保护的，子类可以访问
    
-   子类继承父类的所有非私有成员
    

**在模组开发中的应用：**

所有自定义物品都继承自 `Item` 类：

```java
public class MyCustomItem extends Item {
    public MyCustomItem(Properties properties) {
        super(properties);
    }
    
    // 重写父类方法，实现自定义行为
    @Override
    public InteractionResultHolder<ItemStack> use(Level level, Player player, InteractionHand hand) {
        // 自定义逻辑
        return super.use(level, player, hand);
    }
}
```

#### 2.7.4 多态（Polymorphism）

多态允许使用父类引用指向子类对象，实现"一个接口，多种实现"。

```java
// 父类引用指向子类对象
Item item1 = new Item(new Item.Properties());
Item item2 = new SwordItem(new Item.Properties(), 7);  // SwordItem 是 Item 的子类

// 调用方法时，会根据实际对象类型执行对应的方法
item1.use(level, player, hand);  // 执行 Item 的 use 方法
item2.use(level, player, hand);  // 执行 SwordItem 的 use 方法（如果重写了）
```

**方法重写（Override）：**

子类可以重写父类的方法，提供不同的实现：

```java
public class SwordItem extends Item {
    @Override  // 注解，表示这是重写父类方法
    public InteractionResultHolder<ItemStack> use(Level level, Player player, InteractionHand hand) {
        // 自定义实现
        player.sendSystemMessage(Component.literal("使用了剑！"));
        return InteractionResultHolder.success(player.getItemInHand(hand));
    }
}
```

`@Override` **注解的作用：**

-   编译器会检查父类是否真的有这个方法
    
-   防止拼写错误（如果父类没有这个方法，编译会报错）
    
-   提高代码可读性
    

#### 2.7.5 接口（Interface）

接口定义了一组方法规范，类可以实现（implement）接口。

```java
// 定义接口
public interface ItemLike {
    Item asItem();  // 抽象方法，没有实现
}

// 实现接口
public class DeferredItem<T extends Item> implements ItemLike {
    @Override
    public Item asItem() {
        return this.get();  // 提供具体实现
    }
}
```

**接口 vs 抽象类：**

| 特性 | 接口（Interface） | 抽象类（Abstract Class） |
| --- | --- | --- |
| 多继承 | 一个类可以实现多个接口 | 一个类只能继承一个抽象类 |
| 方法 | 默认都是抽象方法（Java 8+ 可以有默认实现） | 可以有抽象方法和具体方法 |
| 字段 | 只能有常量（`public static final`） | 可以有普通字段 |
| 构造函数 | 不能有构造函数 | 可以有构造函数 |

**在模组开发中的应用：**

从 `DeferredItem.java` 可以看到：

```java
public class DeferredItem<T extends Item> extends DeferredHolder<Item, T> implements ItemLike {
    // 实现 ItemLike 接口
    @Override
    public Item asItem() {
        return this.get();
    }
}
```

这样 `DeferredItem` 就可以在需要 `ItemLike` 的地方使用。

### 2.8 泛型（Generics）

泛型允许在定义类、接口、方法时使用类型参数，提高代码复用性和类型安全。

#### 2.8.1 泛型类

```java
// 定义泛型类
public class Box<T> {
    private T content;
    
    public void set(T content) {
        this.content = content;
    }
    
    public T get() {
        return content;
    }
}

// 使用泛型类
Box<String> stringBox = new Box<>();
stringBox.set("Hello");
String value = stringBox.get();  // 不需要类型转换

Box<Integer> intBox = new Box<>();
intBox.set(123);
Integer number = intBox.get();
```

#### 2.8.2 泛型约束

可以限制泛型参数的类型：

```java
// T 必须是 Item 或其子类
public class DeferredItem<T extends Item> {
    private T item;
    
    public T get() {
        return item;
    }
}

// 使用
DeferredItem<SwordItem> sword = new DeferredItem<>();  // 正确
// DeferredItem<String> invalid = new DeferredItem<>();  // 编译错误！String 不是 Item 的子类
```

**在模组开发中的应用：**

从 `DeferredRegister.java` 可以看到：

```java
public class DeferredRegister<T> {
    // T 是注册表类型（如 Item、Block）
}

public class Items extends DeferredRegister<Item> {
    // 固定 T = Item
}
```

### 2.9 Lambda 表达式与方法引用

Lambda 表达式是 Java 8 引入的特性，用于简化匿名函数的写法。

#### 2.9.1 Lambda 表达式

```java
// 传统写法：匿名内部类
Supplier<Item> supplier = new Supplier<Item>() {
    @Override
    public Item get() {
        return new Item(new Item.Properties());
    }
};

// Lambda 表达式写法
Supplier<Item> supplier = () -> new Item(new Item.Properties());
```

**Lambda 语法：**

```java
// 无参数
() -> expression
() -> { statements; }

// 一个参数
x -> expression
x -> { statements; }

// 多个参数
(x, y) -> expression
(x, y) -> { statements; }
```

#### 2.9.2 方法引用

方法引用是 Lambda 的简化形式：

```java
// Lambda 表达式
Supplier<Item> supplier = () -> new Item(new Item.Properties());

// 方法引用（构造函数引用）
Function<Item.Properties, Item> constructor = Item::new;

// 静态方法引用
Function<String, Integer> parser = Integer::parseInt;

// 实例方法引用
String str = "hello";
Supplier<String> upperCase = str::toUpperCase;
```

**在模组开发中的应用：**

```java
// 注册物品时使用方法引用
public static final DeferredItem<MySword> MY_SWORD = 
    ITEMS.registerItem("my_sword", MySword::new, new Item.Properties());

// 等价于
public static final DeferredItem<MySword> MY_SWORD = 
    ITEMS.registerItem("my_sword", 
        props -> new MySword(props), 
        new Item.Properties());
```

### 2.10 常用集合类

Java 提供了丰富的集合类，用于存储和操作数据。

#### 2.10.1 List（列表）

```java
import java.util.ArrayList;
import java.util.List;

// 创建列表
List<String> items = new ArrayList<>();

// 添加元素
items.add("apple");
items.add("banana");
items.add("cherry");

// 获取元素
String first = items.get(0);  // "apple"

// 遍历
for (String item : items) {
    System.out.println(item);
}

// 大小
int size = items.size();  // 3

// 删除元素
```

### 2.11 异常处理

异常是程序运行时发生的错误。Java 使用 `try-catch` 处理异常。

```java
try {
    // 可能抛出异常的代码
    int result = 10 / 0;  // 会抛出 ArithmeticException
} catch (ArithmeticException e) {
    // 捕获并处理异常
    System.out.println("除数不能为零：" + e.getMessage());
} finally {
    // 无论是否发生异常都会执行
    System.out.println("清理资源");
}
```

**常见异常类型：**

```java

// IllegalArgumentException：非法参数异常
public void setStackSize(int size) {

    }
}

    Files.readString(Path.of("file.txt"));
```

### 2.12 常用设计模式

设计模式是解决常见编程问题的最佳实践方案。NeoForge 源码中大量使用了设计模式，理解它们对阅读源码至关重要。

#### 2.12.1 工厂方法模式（Factory Method）

**问题：** 直接使用 `new` 创建对象可能导致代码耦合度高，难以扩展。

**解决方案：** 使用静态方法创建对象，隐藏创建细节。

**在 NeoForge 中的应用：**

从 `DeferredRegister.java` 可以看到：

```java
// 工厂方法：创建 Items 类型的 DeferredRegister
public static DeferredRegister.Items createItems(String modid) {
    return new Items(modid);
}

// 工厂方法：创建 Blocks 类型的 DeferredRegister
public static DeferredRegister.Blocks createBlocks(String modid) {
    return new Blocks(modid);
}
```

**为什么不直接** `new`**？**

```java
// 不推荐：直接使用构造函数
DeferredRegister<Item> items = new DeferredRegister<>(Registries.ITEM, "yourmod");

// 推荐：使用工厂方法
DeferredRegister.Items items = DeferredRegister.createItems("yourmod");
```

**优点：**

-   隐藏实现细节（你不需要知道 `Registries.ITEM`）
    
-   类型安全（`Items` 类固定了泛型参数）
    
-   易于维护（如果内部实现改变，你的代码不需要修改）
    

**自己实现工厂方法：**

```java
public class ItemFactory {
    // 工厂方法：创建不同类型的物品
    public static Item createSimpleItem() {
        return new Item(new Item.Properties());
    }
    
    public static SwordItem createSword(int damage) {
        return new SwordItem(Tiers.DIAMOND, damage, -2.4f, new Item.Properties());
    }
    
    public static Item createFireResistantItem() {
        return new Item(new Item.Properties().fireResistant());
    }
}

// 使用工厂方法
Item item1 = ItemFactory.createSimpleItem();
SwordItem sword = ItemFactory.createSword(7);
```

#### 2.12.2 建造者模式（Builder Pattern）

**问题：** 当一个类有很多可选参数时，构造函数会变得非常复杂。

**解决方案：** 使用建造者模式，通过链式调用设置参数。

**在 NeoForge 中的应用：**

`Item.Properties` 就是一个典型的建造者：

```java
// 建造者模式：链式调用设置属性
Item.Properties props = new Item.Properties()
    .stacksTo(16)              // 设置堆叠数量
    .durability(250)           // 设置耐久度
    .fireResistant()           // 设置防火
    .rarity(Rarity.RARE);      // 设置稀有度

// 创建物品
Item item = new Item(props);
```

**对比传统构造函数：**

```java
// 如果不用建造者模式，构造函数会变成这样：
public Item(int maxStackSize, int maxDamage, boolean fireResistant, Rarity rarity) {
    // 参数太多，容易搞混顺序
}

// 调用时很难看懂每个参数的含义
Item item = new Item(16, 250, true, Rarity.RARE);  // 这些数字是什么意思？
```

**建造者模式的优点：**

-   参数含义清晰（方法名就是说明）
    
-   可选参数灵活（只设置需要的）
    
-   链式调用优雅
    

**自己实现建造者：**

```java
public class Sword {
    private final int damage;
    private final int durability;
    private final boolean fireResistant;
    
    // 私有构造函数，只能通过 Builder 创建
    private Sword(Builder builder) {
        this.damage = builder.damage;
        this.durability = builder.durability;
        this.fireResistant = builder.fireResistant;
    }
    
    // 建造者类
    public static class Builder {
        private int damage = 5;           // 默认值
        private int durability = 100;     // 默认值
        private boolean fireResistant = false;
        
        public Builder damage(int damage) {
            this.damage = damage;
            return this;  // 返回自己，支持链式调用
        }
        
        public Builder durability(int durability) {
            this.durability = durability;
            return this;
        }
        
        public Builder fireResistant() {
            this.fireResistant = true;
            return this;
        }
        
        public Sword build() {
            return new Sword(this);
        }
    }
}

// 使用建造者
Sword sword = new Sword.Builder()
    .damage(10)
    .durability(500)
    .fireResistant()
    .build();
```

#### 2.12.3 单例模式（Singleton）

**问题：** 某些类在整个程序中只应该有一个实例（如配置管理器、注册表）。

**解决方案：** 使用单例模式，确保只创建一个实例。

**在 Minecraft 中的应用：**

```java
// Minecraft 的注册表就是单例
Registry<Item> itemRegistry = BuiltInRegistries.ITEM;  // 全局唯一的物品注册表
```

**实现单例模式：**

```java
public class ConfigManager {
    // 私有静态实例
    private static ConfigManager instance;
    
    // 私有构造函数，防止外部创建实例
    private ConfigManager() {
        // 初始化配置
    }
    
    // 公开的获取实例方法
    public static ConfigManager getInstance() {
        if (instance == null) {
            instance = new ConfigManager();
        }
        return instance;
    }
    
    // 配置方法
    public void loadConfig() {
        // 加载配置
    }
}

// 使用单例
ConfigManager config = ConfigManager.getInstance();
config.loadConfig();
```

**更好的单例实现（线程安全）：**

```java
public class ConfigManager {
    // 使用枚举实现单例（推荐方式）
    private ConfigManager() {}
    
    private static class Holder {
        private static final ConfigManager INSTANCE = new ConfigManager();
    }
    
    public static ConfigManager getInstance() {
        return Holder.INSTANCE;
    }
}
```

#### 2.12.4 观察者模式（Observer）

**问题：** 当一个对象状态改变时，需要通知多个其他对象。

**解决方案：** 使用观察者模式，对象之间松耦合。

**在 NeoForge 中的应用：**

NeoForge 的**事件系统**就是观察者模式的实现：

```java
// 事件（被观察的对象）
public class PlayerInteractEvent extends Event {
    private final Player player;
    private final ItemStack stack;
    
    // 事件数据
}

// 观察者（事件监听器）
@EventBusSubscriber(modid = "yourmod")
public class EventHandler {
    
    @SubscribeEvent
    public static void onPlayerInteract(PlayerInteractEvent event) {
        // 当事件发生时，这个方法会被调用
        System.out.println("玩家交互了！");
    }
}
```

**观察者模式的组成：**

1.  **主题（Subject）**：被观察的对象（事件）
    
2.  **观察者（Observer）**：监听主题变化的对象（事件监听器）
    
3.  **事件总线（Event Bus）**：管理主题和观察者的关系
    

**自己实现观察者模式：**

```java
// 观察者接口
interface ItemObserver {
    void onItemUsed(Item item);
}

// 被观察的对象
class ItemManager {
    private List<ItemObserver> observers = new ArrayList<>();
    
    // 注册观察者
    public void addObserver(ItemObserver observer) {
        observers.add(observer);
    }
    
    // 通知所有观察者
    public void useItem(Item item) {
        // 执行物品使用逻辑
        System.out.println("使用物品：" + item);
        
        // 通知所有观察者
        for (ItemObserver observer : observers) {
            observer.onItemUsed(item);
        }
    }
}

// 具体观察者
class Logger implements ItemObserver {
    @Override
    public void onItemUsed(Item item) {
        System.out.println("日志：物品被使用 - " + item);
    }
}

class Statistics implements ItemObserver {
    @Override
    public void onItemUsed(Item item) {
        System.out.println("统计：物品使用次数 +1");
    }
}

// 使用
ItemManager manager = new ItemManager();
manager.addObserver(new Logger());
manager.addObserver(new Statistics());
manager.useItem(myItem);  // 会通知所有观察者
```

#### 2.12.5 策略模式（Strategy）

**问题：** 需要在运行时选择不同的算法或行为。

**解决方案：** 将算法封装成独立的类，可以互相替换。

**在 Minecraft 中的应用：**

```java
// 不同的工具材料就是不同的策略
Tier diamondTier = Tiers.DIAMOND;  // 钻石策略
Tier ironTier = Tiers.IRON;        // 铁策略

// 使用不同的策略创建工具
SwordItem diamondSword = new SwordItem(diamondTier, 3, -2.4f, props);
SwordItem ironSword = new SwordItem(ironTier, 3, -2.4f, props);
```

**自己实现策略模式：**

```java
// 策略接口
interface AttackStrategy {
    void attack(Player player, Entity target);
}

// 具体策略1：近战攻击
class MeleeAttack implements AttackStrategy {
    @Override
    public void attack(Player player, Entity target) {
        System.out.println("近战攻击！");
        target.hurt(player.getDamageSources().playerAttack(player), 5.0f);
    }
}

// 具体策略2：远程攻击
class RangedAttack implements AttackStrategy {
    @Override
    public void attack(Player player, Entity target) {
        System.out.println("远程攻击！");
        // 发射箭矢
    }
}

// 使用策略的类
class Weapon {
    private AttackStrategy strategy;
    
    public Weapon(AttackStrategy strategy) {
        this.strategy = strategy;
    }
    
    public void setStrategy(AttackStrategy strategy) {
        this.strategy = strategy;
    }
    
    public void performAttack(Player player, Entity target) {
        strategy.attack(player, target);
    }
}

// 使用
Weapon sword = new Weapon(new MeleeAttack());
sword.performAttack(player, zombie);

Weapon bow = new Weapon(new RangedAttack());
bow.performAttack(player, skeleton);
```

#### 2.12.6 设计模式总结

| 模式 | 用途 | NeoForge 中的例子 |
| --- | --- | --- |
| **工厂方法** | 创建对象，隐藏实现细节 | `DeferredRegister.createItems()` |
| **建造者** | 构建复杂对象，参数清晰 | `Item.Properties`、`CreativeModeTab.builder()` |
| **单例** | 确保只有一个实例 | `BuiltInRegistries` |
| **观察者** | 对象间松耦合通信 | 事件系统（`@SubscribeEvent`） |
| **策略** | 运行时选择算法 | `Tier`（工具材料） |

**学习建议：**

1.  不需要死记硬背所有设计模式
    
2.  在阅读源码时识别这些模式
    
3.  理解为什么要用这个模式
    
4.  在自己的代码中适当使用

## 4\. Gradle 构建系统入门

### 4.1 Gradle 是什么？

Gradle 是一个构建自动化工具，用于：

-   **编译代码**：将 `.java` 文件编译为 `.class` 文件
    
-   **管理依赖**：自动下载项目需要的库
    
-   **打包模组**：将代码和资源打包成 `.jar` 文件
    
-   **运行任务**：执行测试、生成数据等
    

**为什么 NeoForge 使用 Gradle？**

-   Minecraft 模组开发需要复杂的构建流程
    
-   Gradle 可以自动处理反混淆、资源处理等任务
    
-   社区标准，所有现代模组都使用 Gradle
    

### 4.2 Gradle 项目结构

```
yourmod/
├── build.gradle          ← 主构建脚本（最重要！）
├── gradle.properties     ← 配置属性
├── settings.gradle       ← 项目设置
└── gradle/
    └── wrapper/          ← Gradle Wrapper（确保版本一致）
        ├── gradle-wrapper.jar
        └── gradle-wrapper.properties
```

### 4.3 build.gradle 文件解析

这是 NeoForge 模组的典型 `build.gradle` 文件：

```groovy
// 应用插件
plugins {
    id 'java-library'
    id 'eclipse'
    id 'idea'
    id 'maven-publish'
    id 'net.neoforged.gradle.userdev' version '7.0.80'
}

// 项目版本和组
version = '1.0.0'
group = 'com.yourmod'

// Java 版本配置
java {
    toolchain {
        languageVersion = JavaLanguageVersion.of(21)
    }
}

// 依赖配置
dependencies {
    // NeoForge 依赖
    implementation "net.neoforged:neoforge:${neo_version}"
}

// 运行配置
runs {
    client {
        workingDirectory project.file('run')
        systemProperty 'forge.logging.console.level', 'debug'
    }
    server {
        workingDirectory project.file('run')
        systemProperty 'forge.logging.console.level', 'debug'
    }
}
```

**关键配置项：**

| 配置项 | 说明 |
| --- | --- |
| `plugins` | 应用的 Gradle 插件 |
| `version` | 模组版本号 |
| `group` | 模组的包名（通常是反向域名） |
| `java.toolchain` | 指定 Java 版本 |
| `dependencies` | 项目依赖的库 |
| `runs` | 运行配置（客户端/服务端） |

## 6\. 阅读和理解源码的方法论

### 6.1 为什么要阅读源码？

模组开发的本质是**扩展和修改 Minecraft 的行为**。要做到这一点，你必须：

1.  理解 Minecraft 和 NeoForge 的工作原理
    
2.  知道如何正确使用 API
    
3.  学习最佳实践
    

**源码是最好的文档**，因为：

-   官方文档可能过时或不完整
    
-   源码永远是最新的
    
-   源码包含实现细节和注释
    

### 6.2 如何在 IDEA 中查看源码

#### 6.2.1 跳转到定义

```java
// 场景：你想查看 Item 类的源码
Item myItem = new Item(new Item.Properties());
// 选中 "Item" → 按 Ctrl + B → 跳转到 Item.class
```

#### 6.2.2 查看类的层次结构

```java
// 场景：你想知道 Item 有哪些子类
// 选中 "Item" → 按 Ctrl + H → 显示继承树
```

#### 6.2.3 查找用法

```java
// 场景：你想知道某个方法在哪里被调用
// 选中方法名 → 按 Alt + F7 → 显示所有调用位置
```

### 6.3 阅读源码的步骤

#### 步骤 1：从类的 Javadoc 开始

每个类顶部的 `/** ... */` 注释是 Javadoc，它会告诉你这个类的用途。

从 `DeferredRegister.java` 的例子：

```java
/**
 * A helper class to aid in registering objects to modded and
 * {@linkplain BuiltInRegistries vanilla registries} and
 * provide deferred suppliers to access those objects.
 * 
 * <p>This class is designed to be used as a static field in your mod class.
 * ...
 */
public class DeferredRegister<T> {
```

**关键信息：**

-   这是一个辅助类
    
-   用于注册对象到注册表
    
-   应该作为静态字段使用
    

#### 步骤 2：查看静态工厂方法

大多数 NeoForge 类不让你直接 `new`，而是通过静态方法创建：

```java
// 在 DeferredRegister.java 中
public static DeferredRegister.Items createItems(String modid) {
    return new Items(modid);
}
```

**这告诉你：** 创建 `DeferredRegister.Items` 的正确方式是调用 `createItems()`。

#### 步骤 3：查看构造函数

```java
// DeferredItem.java
protected DeferredItem(ResourceKey<Item> key) {
    super(key);
}
```

`protected` **意味着：** 你不能直接 `new DeferredItem()`，必须通过其他方式创建。

#### 步骤 4：查看公开方法

公开方法（`public`）是你可以调用的 API：

```java
// DeferredRegister.java
public <I extends T> DeferredHolder<T, I> register(String name, Supplier<? extends I> sup) {
    // 实现
}
```

**方法签名告诉你：**

-   参数：`name`（字符串）和 `sup`（Supplier）
    
-   返回值：`DeferredHolder<T, I>`
    

#### 步骤 5：查看示例代码

Javadoc 中通常包含示例代码：

```java
/**
 * Example usage:
 * <pre>{@code
 * private static final DeferredRegister.Items ITEMS = DeferredRegister.createItems(MODID);
 * public static final DeferredItem<Item> MY_ITEM = ITEMS.registerSimpleItem("my_item");
 * }</pre>
 */
```

**这是最直接的学习方式**，直接复制示例代码并修改。

### 6.4 理解方法签名

方法签名包含大量信息：

```java
public <I extends T> DeferredHolder<T, I> register(
    final String name, 
    final Supplier<? extends I> sup
)
```

**逐部分解析：**

1.  `public` — 访问修饰符，表示可以在任何地方调用
    
2.  `<I extends T>` — 泛型参数，`I` 必须是 `T` 的子类
    
3.  `DeferredHolder<T, I>` — 返回类型
    
4.  `register` — 方法名
    
5.  `final String name` — 第一个参数，`final` 表示不可修改
    
6.  `final Supplier<? extends I> sup` — 第二个参数，Supplier 类型
    

`Supplier<? extends I>` **的含义：**

-   `Supplier` — 函数式接口，提供一个对象
    
-   `? extends I` — 通配符，表示任何 `I` 的子类
    

**实际使用：**

```java
// Supplier 可以用 Lambda 表达式
ITEMS.register("my_item", () -> new Item(new Item.Properties()));

// 或者方法引用
ITEMS.register("my_item", () -> new MySword(new Item.Properties()));
```

### 6.5 追踪调用链

理解一个功能的完整流程，需要追踪方法调用链。

**示例：注册物品的完整流程**

```java
// 1. 你的代码
ITEMS.registerSimpleItem("my_item");

// 2. registerSimpleItem 调用 registerItem
public DeferredItem<Item> registerSimpleItem(String name) {
    return this.registerItem(name, Item::new);
}

// 3. registerItem 调用 register
public <I extends Item> DeferredItem<I> registerItem(String name, Function<Item.Properties, I> func) {
    return this.register(name, () -> func.apply(new Item.Properties()));
}

// 4. register 创建 DeferredHolder 并存储
public <I extends T> DeferredHolder<T, I> register(String name, Supplier<? extends I> sup) {
    DeferredHolder<T, I> ret = createHolder(this.registryKey, key);
    entries.putIfAbsent(ret, sup);
    return ret;
}
```

**追踪方法：**

1.  选中方法名 → `Ctrl + B` → 跳转到定义
    
2.  查看方法内部调用了哪些方法
    
3.  继续跳转，直到理解整个流程
    

### 6.6 理解注解（Annotations）

注解提供元数据，影响代码行为。

**常见注解：**

```java
@Override  // 表示重写父类方法
public void use() { }

@Nullable  // 表示返回值可能为 null
public Item getItem() { }

@NotNull  // 表示参数不能为 null
public void setItem(@NotNull Item item) { }

@Deprecated  // 表示方法已过时，不推荐使用
public void oldMethod() { }
```

**NeoForge 特有注解：**

```java
@Mod("yourmod")  // 标记模组主类
public class YourMod { }

@EventBusSubscriber  // 自动注册事件监听器
public class EventHandler { }

@OnlyIn(Dist.CLIENT)  // 仅在客户端执行
public void clientOnlyMethod() { }
```

## 7\. 模组开发核心概念

### 7.1 注册系统（Registry System）

#### 7.1.1 什么是注册表？

Minecraft 使用**注册表（Registry）**来管理所有游戏对象：

```
注册表类型：
├── ITEM（物品）
├── BLOCK（方块）
├── ENTITY_TYPE（实体类型）
├── SOUND_EVENT（声音事件）
├── PARTICLE_TYPE（粒子类型）
└── ... 还有很多
```

每个对象都有一个唯一的 **ResourceLocation**（资源位置）：

```
格式：命名空间:路径
示例：minecraft:diamond
      yourmod:my_item
```

#### 7.1.2 为什么需要延迟注册？

**问题：** 游戏启动时，各个模组的加载顺序不确定。如果你在错误的时间注册对象，游戏会崩溃。

**解决方案：** NeoForge 的 `DeferredRegister` 系统：

```java
// 第一步：创建 DeferredRegister（模组加载时）
public static final DeferredRegister.Items ITEMS = DeferredRegister.createItems("yourmod");

// 第二步：注册对象（类加载时）
public static final DeferredItem<Item> MY_ITEM = ITEMS.registerSimpleItem("my_item");

// 第三步：将 DeferredRegister 绑定到事件总线（模组构造函数中）
public YourMod(IEventBus modEventBus) {
    ITEMS.register(modEventBus);
}

// 第四步：NeoForge 在正确的时间触发 RegisterEvent，实际创建对象
```

**关键点：**

-   `registerSimpleItem()` 只是记录"要注册什么"
    
-   实际对象在 `RegisterEvent` 触发时才创建
    
-   这确保了注册顺序的正确性
    

#### 7.1.3 DeferredHolder 的作用

`DeferredHolder` 是一个"占位符"，它会在注册完成后指向实际对象：

```java
public static final DeferredItem<Item> MY_ITEM = ITEMS.registerSimpleItem("my_item");

// 在注册完成前
MY_ITEM.get();  // 可能返回 null 或抛出异常

// 在注册完成后
MY_ITEM.get();  // 返回实际的 Item 对象
```

**使用场景：**

```java
// 在配方中引用物品
public void createRecipe(RecipeOutput output) {
    ShapedRecipeBuilder.shaped(RecipeCategory.TOOLS, MY_ITEM.get())
        .pattern("###")
        .pattern(" | ")
        .pattern(" | ")
        .define('#', Items.DIAMOND)
        .define('|', Items.STICK)
        .save(output);
}
```

### 7.2 事件系统（Event System）

#### 7.2.1 什么是事件？

事件是游戏中发生的特定动作，如：

-   玩家右键点击
    
-   实体受到伤害
    
-   方块被破坏
    
-   物品被合成
    

NeoForge 允许你**监听**这些事件并执行自定义代码。

#### 7.2.2 两种事件总线

**1\. Mod 事件总线（Mod Event Bus）**

用于模组生命周期事件：

```java
@Mod("yourmod")
public class YourMod {
    public YourMod(IEventBus modEventBus) {
        // 监听注册事件
        modEventBus.addListener(this::onRegister);
        
        // 监听客户端设置事件
        modEventBus.addListener(this::onClientSetup);
    }
    
    private void onRegister(RegisterEvent event) {
        // 注册对象
    }
    
    private void onClientSetup(FMLClientSetupEvent event) {
        // 客户端初始化
    }
}
```

**2\. 游戏事件总线（Game Event Bus）**

用于游戏运行时事件：

```java
@EventBusSubscriber(modid = "yourmod")
public class EventHandler {
    
    @SubscribeEvent
    public static void onPlayerInteract(PlayerInteractEvent.RightClickItem event) {
        // 玩家右键物品时触发
        Player player = event.getEntity();
        ItemStack stack = event.getItemStack();
        
        if (stack.is(ModItems.MY_ITEM.get())) {
            player.sendSystemMessage(Component.literal("你使用了我的物品！"));
        }
    }
    
    @SubscribeEvent
    public static void onLivingHurt(LivingHurtEvent event) {
        // 实体受伤时触发
        if (event.getEntity() instanceof Player player) {
            // 玩家受伤时的逻辑
        }
    }
}
```

**关键区别：**

| 特性 | Mod 事件总线 | 游戏事件总线 |
| --- | --- | --- |
| 获取方式 | 构造函数参数 | `NeoForge.EVENT_BUS` |
| 事件类型 | 模组生命周期 | 游戏运行时 |
| 注册方式 | `modEventBus.addListener()` | `@EventBusSubscriber` + `@SubscribeEvent` |
| 示例事件 | `RegisterEvent`、`FMLClientSetupEvent` | `PlayerInteractEvent`、`LivingHurtEvent` |

#### 7.2.3 事件的优先级

可以设置事件监听器的优先级：

```java
@SubscribeEvent(priority = EventPriority.HIGH)
public static void onPlayerInteract(PlayerInteractEvent event) {
    // 高优先级，会比其他监听器先执行
}
```

**优先级顺序：**`HIGHEST` → `HIGH` → `NORMAL`（默认）→ `LOW` → `LOWEST`

#### 7.2.4 取消事件

某些事件可以被取消：

```java
@SubscribeEvent
public static void onBlockBreak(BlockEvent.BreakEvent event) {
    // 阻止玩家破坏钻石矿
    if (event.getState().is(Blocks.DIAMOND_ORE)) {
        event.setCanceled(true);
        event.getPlayer().sendSystemMessage(Component.literal("你不能破坏钻石矿！"));
    }
}
```

**注意：** 只有标记为 `@Cancelable` 的事件才能被取消。

### 7.3 资源位置（ResourceLocation）

`ResourceLocation` 是 Minecraft 中标识资源的方式：

```java
// 创建 ResourceLocation
ResourceLocation loc1 = ResourceLocation.fromNamespaceAndPath("yourmod", "my_item");
ResourceLocation loc2 = ResourceLocation.parse("yourmod:my_item");  // 等价

// 获取命名空间和路径
String namespace = loc1.getNamespace();  // "yourmod"
String path = loc1.getPath();            // "my_item"

// 转换为字符串
String str = loc1.toString();  // "yourmod:my_item"
```

**使用场景：**

```java
// 注册物品时自动创建 ResourceLocation
ITEMS.registerSimpleItem("my_item");  // 内部创建 "yourmod:my_item"

// 引用原版物品
Item diamond = BuiltInRegistries.ITEM.get(ResourceLocation.withDefaultNamespace("diamond"));

// 加载贴图
ResourceLocation texture = ResourceLocation.fromNamespaceAndPath("yourmod", "textures/item/my_item.png");
```

### 7.4 客户端与服务端

Minecraft 分为**客户端（Client）和服务端（Server）**：

```
单人游戏：
┌─────────────┐
│   客户端     │ ← 渲染、输入、声音
│   +         │
│   服务端     │ ← 游戏逻辑、世界管理
└─────────────┘

多人游戏：
┌─────────────┐          ┌─────────────┐
│   客户端     │ ←网络→  │   服务端     │
│  (玩家1)    │          │  (专用服务器) │
└─────────────┘          └─────────────┘
       ↑
       网络
       ↓
┌─────────────┐
│   客户端     │
│  (玩家2)    │
└─────────────┘
```

**重要原则：**

-   **逻辑代码**应该在服务端执行
    
-   **渲染代码**只能在客户端执行
    
-   使用 `level.isClientSide()` 判断当前环境
    

```java
@Override
public InteractionResultHolder<ItemStack> use(Level level, Player player, InteractionHand hand) {
    if (!level.isClientSide()) {
        // 服务端逻辑
        player.sendSystemMessage(Component.literal("服务端消息"));
    } else {
        // 客户端逻辑（通常用于渲染或声音）
        // 注意：不要在这里修改游戏状态！
    }
    return InteractionResultHolder.success(player.getItemInHand(hand));
}
```

**仅客户端代码：**

```java
@OnlyIn(Dist.CLIENT)
public class ClientHandler {
    public static void registerRenderers() {
        // 注册渲染器
    }
}
```

### 7.5 数据生成（Data Generation）

数据生成允许你用 Java 代码生成 JSON 文件（模型、配方、标签等）。

**为什么使用数据生成？**

-   避免手写大量重复的 JSON
    
-   类型安全，编译时检查错误
    
-   易于维护和批量修改
    

**示例：生成物品模型**

```java
        super(output, "yourmod", existingFileHelper);

        // 生成手持工具模型

    }
}
```


生成的文件会保存在 `src/generated/resources/` 目录。

```java
import net.minecraft.core.registries.Registries;

            .build());

        ModItems.register(modEventBus);

    }
```

### 8.8 常见错误排查

#### 8.8.1 物品不显示

**可能原因：**

1.  模型文件路径错误
    
2.  贴图文件缺失
    
3.  物品未添加到创造模式标签页
    

**排查步骤：**

1.  检查文件路径是否正确（区分大小写）
    
2.  查看游戏日志（`run/logs/latest.log`）
    
3.  搜索错误信息：`Missing texture` 或 `Model not found`
    

#### 8.8.2 游戏崩溃

**可能原因：**

1.  注册时机错误
    
2.  空指针异常（`NullPointerException`）
    
3.  类加载错误
    

**排查步骤：**

1.  查看崩溃报告（`crash-reports/` 文件夹）
    
2.  找到 `Caused by:` 行，查看具体错误
    
3.  根据错误信息搜索解决方案
    

#### 8.8.3 物品名称显示为 ID

**原因：** 缺少语言文件或翻译键错误

**解决方案：**

1.  检查 `lang/zh_cn.json` 是否存在
    
2.  验证翻译键格式：`item.{modid}.{item_id}`
    
3.  确保文件编码为 UTF-8
